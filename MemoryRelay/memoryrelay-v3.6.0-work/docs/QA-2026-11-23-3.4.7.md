# MemoryRelay v3.4.7 · Source and visual QA

Tested on November 23, 2026, from the supplied v3.3.8 audited source plus the in-progress v3.4.x UI changes.

## Findings and changes

- All remaining `<select>` elements were replaced in active frontend components. Native Android option-sheet behavior is no longer invoked by Skills sort, skill count, repository update policy or imported-file type.
- Library totals appear as compact Overview cards before monitored usage.
- Repository management is a full sub-screen with tabs, not an expandable row.
- Chart.js line series use a soft vertical gradient with distinct stable colors for each metric.
- New generated logo assets are opaque and PWA maskable assets include padding for circle/squircle masks.
- Animated welcome runs once per page load. No spinner/dot. Composite-only transitions with `prefers-reduced-motion` guard.

## Verification

- Node test runner: **165 passed, 0 failed, 1 skipped** (`npm test`). Skipped test requires external upstream data.
- Headless Chromium static CSS/markup fixtures: 390 px and 430 px screenshots for welcome, Overview, repositories, dedicated repo screen and Markdown reader. All sampled widths had `document.documentElement.scrollWidth <= innerWidth`.
- PNG metadata: source tests verify 192/512 and maskable icons and no-dot SVG.
- `npm run build`: **not completed** in this environment (`vite: not found`); npm registry install unavailable. Requires validation on user’s Debian environment before commit/push.
- Production live app, real Android PWA launcher reinstallation, authenticated in-app navigation, and dynamic backend data were **not tested**. Static visual fixtures do not prove full React render correctness.

## Known limitations

- Existing installed PWA launchers can cache their icon until Chrome refreshes installed app metadata or the user reinstalls. Refreshing browser tab may not update launcher art.
- User device should verify tap menus, keyboard focus, safe-area insets, service worker update and sign-in after deployment.
- The first activation may briefly display the welcome for ~850 ms; subsequent in-app navigation is not delayed.
