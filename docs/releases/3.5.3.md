# MemoryRelay v3.5.3 — Edit API keys, Gemini model loading, Errors screen

**Date:** 2026-11-24  
**Baseline:** v3.5.2

## Reported problems
1. No way to edit an API key.
2. Loading Gemini models failed with `HTTP 400 (check the key)` although the key was valid; the model drop-down stayed empty.
3. The model list should contain text-generation models only.
4. The Errors screen could not be scrolled.
5. "Back to overview" did nothing.

## Causes and fixes
1. **Edit key** (`edit_key` op on `/api/gemini` and `/api/{openrouter,nvidia,openai}`; Edit key button in each key's drawer). Rename, replace the key, or both. A replaced key is stored with the same encryption as new keys, re-enabled, and its cooldowns are cleared. Duplicates of another saved key are refused.
2. **Real reason shown.** The server used to hide Google's answer behind a generic message. It now reports `HTTP <status> <STATUS>: <message>` (key-like strings redacted) with a hint for expired keys and unsupported regions. Google also answers 400 for an unsupported Worker location or an expired key, not only for a wrong key, so the exact message tells which it is. Pasted keys are cleaned (surrounding quotes, zero-width characters) and refused if they contain spaces. The Gemini panel shows errors in the error colour.
3. **Text models only.** `generateContent` models named gemini/gemma, excluding embedding, image, video, audio, speech, live and similar models. Results are read across up to 5 pages (200 per page) instead of the first 100 only. If Google lists none, the message says so and suggests typing a model name.
4. **Errors scrolling.** The screen was rendered directly in the non-scrolling main area; it now has its own scrolling pane with the normal padding.
5. **Back to overview.** It called the tab selector, which ignored the tap because Live was still the remembered tab. Selecting a tab now only scrolls to top when that tab is really showing; otherwise it navigates.
6. Related: model browsing for OpenRouter/NVIDIA/OpenAI sent the stored value directly, which is ciphertext when `KEY_SECRET` is set. It now opens the key first.
