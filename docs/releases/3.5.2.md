# MemoryRelay v3.5.2 — Key-free housekeeping and paged `recent`

**Date:** 2026-11-24  
**Baseline:** v3.5.1

## Problem
- MCP `housekeep` depended on a server-side AI provider. With every Gemini key rejected and no NVIDIA/OpenRouter model enabled, it failed outright.
- `recent` ignored any offset, so only the newest 20 full memories could be read.

## Changes
1. **Key-free housekeeping over MCP.** `housekeep` (default) returns `candidate_groups`: memories with the same app and version whose words overlap at least `min_similarity` (default 0.6, range 0.3-1). Each member shows id, date, description, length and a 160-character preview. The agent reads each with `get_memory`, merges with `update_memory`, and removes extra copies with `forget`. Nothing is written by `housekeep` itself.
2. **Rules stay protected.** Rules-tagged memories are never listed (only counted as `rules_memories_skipped`), and `update_memory` / `forget` still refuse them.
3. **AI path unchanged for owners.** `housekeep` with `ai: true` returns the server-AI preview over MCP; applying it is refused over MCP and happens only in the owner dashboard. If no AI provider works, the dashboard preview falls back to an offline exact/near-identical check (no merged text) and says so.
4. **`recent` paging.** New `offset` argument; result includes `offset` and `next_offset` (null at the end).
5. MCP arguments of type number are now validated.
