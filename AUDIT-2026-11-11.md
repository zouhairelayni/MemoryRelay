# MemoryRelay audit, 2026-11-11 (all patches done, 134 tests pass)

## Why skills stayed stuck / GitHub said 403
- A sync checks 8 files per run. Cron only resumed repos with auto-sync ON, so repos with auto-sync OFF stayed at 8/27, 8/18, 8/10 forever. Cron now resumes any started queue; "Sync now" in the app keeps going until finished.
- A failure stamped last_checked, so cron waited 24 h before retrying a repo that never synced. Now: retry after 10 min; the 24 h wait only follows a successful check.
- A skill whose SKILL.md name differs from its folder (taste-skill) or a file that 404s froze the whole queue. Now it is skipped and listed under the repo ("sync_note").
- 403: without GITHUB_TOKEN GitHub allows 60 requests/hour per shared Cloudflare address, so the quota is often already used by others. Now: the Worker pauses ALL repos until GitHub's reset time (no wasted requests), uses ETag (304 replies are free), takes a lease so cron and the app never double-run, and shows the reset time in the app. Adding a GITHUB_TOKEN secret (npx wrangler secret put GITHUB_TOKEN) is the real fix: 5,000/hour.

## "ponytail / ponytail-audit do not exist"
Agents could only reach skills through select_skills (a ranker with 3 slots, and the AI could answer "none"). Now: a skill named in the request is always sent, new tools get_skill (exact name, explains unknown or switched-off) and list_skills, and the empty answer tells the agent to check before concluding a skill is missing. Update your agent's connector so it sees the two new tools.
NOTE: skills added from GitHub never replace a pasted skill of the same name; that is now listed in the repo note.

## Lag
- Built-in seeding never marked itself done: ~6 D1 reads + 1 write on EVERY request. Fixed.
- Skills list loaded every full body (official skills are huge) and an unindexed join; now reads 30 KB per skill and has an index.
- Every dashboard poll wrote an activity row and the table was never pruned; now only changes/failures are logged and rows older than 90 days are deleted hourly.
- select_skills could wait up to 150 s on the AI; now capped at 14 s, then keywords. Gemini key rotation no longer costs 2 D1 calls.
- GitHub sources screen polled every 12 s even when hidden; now only when visible.

## Security
- local.db in the zip held a plaintext admin password: removed; *.db ignored. Change any real password that was ever the same.
- server.js dev stub accepted any login with CORS "*": now loopback + localhost origins only, labelled dev-only.
- Login lock never reset after expiry (one typo = another 15 min); fixed, expired rows pruned.
- Memory import read an unbounded body: capped at 12 MB.
- get_skill_script / get_skill_resource ignored the on/off switch: now enabled skills only.
- GitHub text: hidden direction-changing/zero-width characters are refused; unattended updates that newly add injection-style wording are held back for your review (manual Sync now applies them with a warning).
- A Gemini 403 for one model no longer disables the whole key.

## Not changed (your call)
- First visitor can create the owner account unless SETUP_TOKEN is set: set it.
- API keys are stored in plain text in D1 (normal for a personal Worker).
- Delegation deadline (previous audit item 5) untouched.
- UI was syntax-checked only (no node_modules offline): run `npm run build` once.

# Round 2 (2026-11-12): sync reporting, scripts/tests/fonts, filters (138 tests pass)
- Why "synced" said nothing: a pasted skill with the same name blocks the repo's copy (e.g. pbakaus/impeccable). Now each repo shows the real result (new / updated / taken over / unchanged / held back), a skill counter and file counters (scripts, tests, fonts, reference docs).
- Existing skill or repo is detected: adding a repo twice says "already tracked (N skills imported)"; same-name pasted skills are listed with where they come from; a missing repo/branch ("Repository or branch not found"), a wrong folder ("No skills found") and unknown skill names are reported instead of "synced".
- "Replace pasted skills with the same name" (per repo, off by default): the repo takes over the pasted skill, the old text stays in history.
- File settings per repo: kinds (scripts .py .mjs .cjs .js .ts .sh, tests *.test.* / tests/ folders, fonts .woff2 .woff .ttf .otf, reference docs .md .json .yaml...), path filter (one pattern per line, `!` excludes, e.g. `scripts/**`, `*.mjs`, `!**/fixtures/**`), largest file (50-1000 KB). Defaults: scripts + tests. node_modules, lock files, .min files and LICENSE are never imported. Changing the settings restarts that repo's sync.
- Fonts are stored as base64 (every byte kept). Delivery to agents: the skill text lists every file by kind and size, short scripts/tests travel inline, get_skill_resource returns any file (no path = list all), and big files and fonts come in parts (offset / next_offset).
- A sync now handles 12 files per run (was 8).

# Round 3 (2026-11-12): file management and GitHub quota (142 tests pass)
- Each repo has "Imported files (N)": files grouped by skill with kind and exact size, search and type filter, text preview, Remove and Restore. A removed file is remembered (excluded_files) so later syncs do not bring it back; Restore clears the last checked revision so the next Sync now fetches it. Only files of skills that came from that repo can be removed through it.
- Quota: a manual Sync now no longer spends 2 requests when nothing is pending: it sends the ETag and an unchanged branch answers 304, which GitHub does not count. It still does the full check when new skills were left uninstalled, an update is held back, or the last sync had problems. "Re-check everything" (in File settings) always does the full check.
- GitHub quota (left / limit / reset, and whether a token is in use) is remembered from the response headers of every API call and shown at the top of the screen, at no cost.
- Still open (not asked): SETUP_TOKEN enforcement, API-key encryption, delegation deadline, OAuth client registration, wider hold-back of unattended updates.

# Round 4 (2026-11-12), part 1 (144 tests pass)
- Setup lock: on a deployed host (anything but localhost) the first-run account page is refused until a SETUP_TOKEN secret exists; the screen explains how to add it. Local development stays open.
- Delegation: one shared time budget per job (default 110 s, owner-tunable via config dg_budget_ms, 20-170 s). Each provider call is capped by what is left; a review or repair that no longer fits is skipped and reported ("time budget ran short: skipped ..."), and a requested review that was skipped never counts as a pass.
- OAuth client registration was re-checked: already limited to 20/hour per address, capped in number, unused clients pruned, redirect addresses validated, and the consent page shows where it returns to. No change needed.

# Round 4 part 2 (2026-11-12)
- API keys at rest: with a KEY_SECRET secret, Gemini/OpenRouter/NVIDIA/OpenAI keys are stored as AES-GCM ciphertext (PBKDF2-derived key, random IV per key, last 4 characters kept readable for the dashboard). Existing keys are converted once on the next request; the same key added twice is saved once; without the secret an encrypted key is reported as "KEY_SECRET is missing or wrong" instead of failing mysteriously. Without KEY_SECRET nothing changes. Keep the secret: if it is lost, re-add the keys.
- Unattended updates per repo ("Automatic updates" in File settings): safe (default) holds updates that add risky wording; review holds every change, including changed scripts and tests; all applies everything. Held updates wait until you press Sync now. Changed scripts/tests now also count as "updated" in the sync summary.

# Round 5 (2026-11-13): skills are not only in skills/
Reported with impeccable, ui-audit, ui-ux-pro-max-skill and taste-skill. Causes: the folder defaulted to `skills`, only `skills/<name>/SKILL.md` was looked at, and a SKILL.md whose name differed from its folder (taste-skill declares design-taste-frontend) was refused.
- Folder is now optional (empty = automatic). Every SKILL.md in the repository counts, at any depth: `.claude/skills/x/`, `plugins/ui/skills/x/`, a single SKILL.md at the repo root. The folder field only narrows the search. A folder that holds nothing falls back to searching everywhere and the repo then keeps looking everywhere. Links like github.com/owner/repo/tree/<branch>/<folder> are understood.
- Each file goes to the nearest skill folder above it, so a skill at the repo root does not swallow the other skills' files; node_modules and .git never count.
- The same skill shipped for several tools (.claude/, .cursor/, plugin/...) is installed once, preferring a visible skills/ folder; the ignored copies are counted in the repo note. Two folders declaring the same name also install once.
- A skill is installed under the name its SKILL.md declares, so taste-skill is imported as design-taste-frontend. A remembered folder-to-name map keeps automatic updates working. A name already used by a pasted skill is still reported (and can be taken over), and its files are not downloaded.
- "No SKILL.md file found anywhere" is shown when a repository really has none. Existing repos that found nothing are re-checked once after this update (Sync now on repos with auto-sync off).
- File settings gained an editable Skills folder.
